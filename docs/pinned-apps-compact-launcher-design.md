# 固定 App 与小窗启动模式设计方案

日期：2026-09-11。状态：用户已选择第 3 张作为视觉基础，并要求双图标直接切换、取消固定角标；用户已授权开始实现。

## 最新界面调整（2026-09-11）

用户后续要求优先于下文初版细节：全屏独立小屏按钮移入齿轮设置菜单；小屏搜索框最大 360 pt，导航/全屏图标 12 pt，设置采用齿轮；负一屏设置文案改为「开启」「布局」；固定管理只提供取消固定，移除添加、前移/后移与设置列表拖动。网格中的固定拖动排序继续保留。

## 1. 设计目标与约束

让常用入口更稳定，并提供接近用户截图中系统“应用程序”面板大小的小窗启动台。小窗仍然是图标网格，有搜索和文件夹，不是单行命令搜索框。

已确定的约束：

- 保留全屏模式；升级后仍以全屏为默认，不突然改变现有启动体验。
- 负一屏继续支持开关、默认 6×4 / 最多 24 个、可选 7×5 / 最多 35 个。
- 固定与常用项合计占用上述容量，不额外加一行、不扩展负一屏页数。
- 网格紧凑、末行左对齐，不添加“猜你想用”“按你……”或固定/推荐分区标题。
- 小窗采用第 3 张的单行工具栏布局；常用与全部使用两个图标直接切换，不使用文字下拉菜单。
- 固定 App 不显示图钉或任何替代角标，全屏与小窗统一保持干净的图标外观。
- 普通应用页和文件夹布局是唯一真实布局；固定入口是引用，不移动、不复制应用记录。
- 继续支持中文、英文、全拼、拼音首字母搜索。
- 不新增屏幕采集、摄像头、麦克风、联网推荐或全局使用行为统计。

导航外观以本次用户选择和修改意见为准；其他拟议默认值与首版取舍在本文明确列出，功能实现已获用户授权。

## 2. 当前实现与设计依据

本轮已检查当前工作区源码：

| 模块 | 当前行为 | 对本次设计的影响 |
| --- | --- | --- |
| `RecommendationPreferences` | 保存负一屏开关、布局、排除名单，支持旧备份默认值 | 在同一偏好所有者内增加有序固定列表，避免重复数据源 |
| `ApplicationRecommendationEngine` | 以 bundle identifier / 路径作为 key；只选 `openCount > 0` 的 App | 固定项必须有独立资格检查，允许固定从未启动的 App |
| `ApplicationRecommendationSnapshot` | 每次展示生成排名快照，期间移除无效项 | 保留打开期间不自动跳位的原则，主动固定操作可立即更新 |
| `KidoXStore` | 所有应用、搜索、启动记录和推荐快照；拥有全屏页面身份 | 小窗与全屏共享一个 store，不另建扫描或使用计数体系 |
| `LauncherPresentationPage` | 负一屏为展示页，不写入真实布局页 | 固定排序不触发普通页的拖拽、分组和持久化代码 |
| `KidoXPanelController` | 当前面板覆盖屏幕；负责唤起、焦点、手势、外部点击和动画 | 需要独立的小窗展示策略，不是把现有大网格简单缩放 |
| `SettingsView` | 备份结构目前为 schema 1，内嵌推荐偏好字段 | 新增可选字段，读旧备份安全默认；不无故升级数据库结构 |

当前负一屏仅在默认排序且没有搜索时出现。普通页在同一次进程运行中记忆上次页面，完全退出后从普通第一页开始。这些行为保留。

参考截图提供的是裁切后的图像，无法由图片判断实际 macOS 点数与显示缩放。因此下面的窗口尺寸是初始设计值，不声称是 Apple 面板的精确尺寸。

## 3. 负一屏固定 App

### 3.1 入口与菜单

在普通应用页、文件夹内、全局搜索结果、小窗以及负一屏中，应用右键菜单加入：

- 未固定：`固定到负一屏`。
- 已固定：`取消固定`。
- 负一屏中未固定的自动推荐项：继续提供 `不再推荐此应用`。
- 固定项不同时显示“不再推荐”，避免“固定但又排除”的相互矛盾状态。
- 文件夹本身不能固定；文件夹内的 App 可以固定。

负一屏关闭时，固定列表依旧可编辑和保存；点击固定后给一次轻提示 `已固定，开启负一屏后显示`，不擅自开启。非默认排序同样允许管理固定项，但提示其在默认排序的负一屏显示。

固定项与其他应用使用相同的图标外观，不显示图钉、星标、圆点或其他替代角标，悬停也不追加角标。固定状态通过右键菜单中的“取消固定”、设置中的固定列表和 VoiceOver 的“已固定”描述识别。键盘焦点仅使用普通选择样式，不增加固定专属装饰；固定列表靠前排列和拖动规则不变。

### 3.2 排序与容量

展示序列为：有序且有效的固定项 + 排除固定 key 后的常用快照，最终截取布局容量。

例：6×4 布局、4 个固定 App，剩余最多 20 个位置由常用 App 补足；固定与常用之间不留空位、不加分隔线。

规则：

1. 新固定项加入固定列表末尾；从未通过 KidoX 启动过也可以显示。
2. 固定项可在负一屏中拖动排序，只改变固定列表顺序。
3. 首版不通过拖动自动推荐项来隐式固定；先右键固定，再拖动。自动推荐项保持点击启动和右键排除。
4. 固定拖动只接受固定区域中的有效落点；拖到推荐区域尾部等价于固定列表末尾，拖出面板取消操作，不生成文件夹或移动原应用。
5. 取消固定不等于排除。App 若在当前常用候选快照内，可继续在自动部分显示；提示 `已取消固定，仍可能出现在常用应用中`。
6. 修改固定顺序立即生效；启动次数增长不在当前打开期间触发排名跳动。固定、取消固定使用同一次会话冻结的候选顺序重新组合，不重新排序全部应用。
7. 保留现有“排除立即移除、恢复下次打开参与推荐”的行为。异步发现不可用应用时移除该项，不因扫描而自动重排其他项。

固定列表最多保存 35 项。当已保存固定记录数达到当前布局容量时，新增固定操作不可用，并提示切换更大布局或管理已有固定项。这里仅计算固定记录，不计算自动推荐项；例如 4 固定 + 20 推荐仍然可以继续固定，推荐自动让出位置。

从 7×5 改为 6×4 时，保存的第 25～35 个固定项不会删除；只有前 24 个有效固定项显示，设置中提示 `当前布局未显示 N 个固定应用`。切回 7×5 自动恢复。隐藏或未安装项不占可见格子，但仍占固定列表保存名额；管理界面明确标识。

### 3.3 隐藏、排除、安装状态

| 情况 | 行为 |
| --- | --- |
| 应用隐藏，或父文件夹隐藏 | 不显示，保留固定记录；取消隐藏后恢复 |
| 应用卸载 / 路径无效 | 不显示占位图标；管理列表显示“未安装”，允许移除 |
| 同 bundle identifier 应用重新安装 | 扫描确认有效后可重新解析固定引用；无 bundle identifier 的路径变化需重新固定 |
| 同 App 有重复扫描记录 | 沿用统一 key 去重，解析为一个有效目标 |
| 曾经“不再推荐”，后来明确固定 | 一次偏好事务中移出排除名单并固定 |
| 导入备份时同时固定与排除 | 固定的显式意图优先，规范化时移除对应排除记录；隐藏仍优先于展示 |
| 负一屏开关关闭 | 只关闭入口，固定顺序、布局和排除数据全部保留 |

不根据显示名称识别 App，避免中文名、英文名切换造成固定丢失。

### 3.4 设置与管理

在现有「设置 → 通用 → 负一屏」增加 `固定应用（N）` 管理区域：

- 列出图标、名称、顺序，以及未安装/隐藏/受当前容量限制状态。
- 支持拖动调整、单项取消固定；同时提供键盘可操作的前移/后移。
- `添加应用…` 打开可搜索的已安装 App 选择界面，能添加尚未出现在负一屏的应用。
- 添加与排除冲突按上述规则一次处理；不可选择文件夹和已固定的重复项。
- 无固定项时显示简短引导 `右键应用可固定到负一屏`，只出现在管理区域。

## 4. 小窗启动模式

### 4.1 设置与唤起

设置新增「启动方式」单选：`全屏` / `小窗`，默认全屏。采用互斥选项表达模式，避免“启用小窗”与另一默认启动方式互相冲突。

- Dock、菜单栏、F4、已有快捷键、热角均遵循用户选择。
- 已开启的四指手势也遵循该选择；小窗使用简短淡入/缩放，不套用全屏交互形变动画。
- 重复触发当前打开的启动台会关闭；任一时刻只显示一个启动台面板。
- 小窗右上角展开按钮可临时切到全屏，全屏提供返回小窗入口；临时切换不改设置中的默认方式。
- 设置中改模式，下次唤起生效；不在用户拖拽、输入或菜单展开中途替换窗口。
- 首版不增加第二组默认全局快捷键，以避免快捷键冲突和设置复杂度。

### 4.2 尺寸与外观

| 项目 | 初始设计值 |
| --- | --- |
| 标准窗口 | 约 920×640 pt，宽高比接近参考图 |
| 默认位置 | 鼠标所在屏幕的可用区域中心，避开菜单栏和 Dock |
| 屏幕边距 | 通常至少 24 pt；低分辨率时按可用区域收缩 |
| 外形 | 约 26 pt 圆角、细边缘、柔和阴影、原生半透明底色 |
| 工具栏 | 单行排列：小号 KidoX 标识、常用/全部双图标、搜索框、展开和更多菜单 |
| 应用图标 | 通常 64 pt，窄屏可降至 56 pt，不把整个界面等比缩小 |
| 标签 | 约 14 pt，长名称一行省略，悬停显示全名 |
| 普通列表 | 标准宽度 7 列，约 4 行完整可见，其余纵向滚动 |
| 负一屏 | 遵循 6×4 / 7×5；6 列内容设宽度上限，不拉满产生巨大空隙 |

默认窗口高度下 7×5 使用更紧凑的行距，目标完整容纳 35 项；如果屏幕高度、辅助功能文字尺寸不允许，则仅内容区滚动，不裁掉最后一行。列数保持所选负一屏布局，低宽度进一步减小间距；极小可用区域须给出可访问的滚动后备策略，不强制超出屏幕。

允许拖动顶部空白区域移动窗口；拖图标不移动窗口。首版不提供任意缩放和长期置顶。位置仅按显示器在当前运行期间记忆，显示器移除或坐标越界后重新居中，不把设备坐标写入备份。

背景使用系统材质，跟随浅色/深色及降低透明度设置；小窗不继承全屏自定义壁纸铺满效果，全屏外观偏好继续保留。开启“减少动态效果”时用淡入淡出，避免弹跳。具体玻璃观感需在目标系统实测，概念图不是原生渲染保证。

### 4.3 浏览结构与已选导航

保留两种内容：`常用`、`全部`。小窗中的“常用”就是现有负一屏数据，包含固定和自动推荐；这两个名称仅用于悬停提示和辅助功能标签，不在工具栏常驻显示文字，不新增“猜你想用”标题。

- 常用：只显示共享的负一屏，不另算推荐、不另存固定顺序。
- 全部：按现有普通页顺序串联根级项目，保留文件夹；不显示原页间空槽。只做展示投影，不把 7 列重新写回普通页布局。
- 默认排序之外，全部遵循现有排序规则的结果；常用入口按现有约束暂时隐藏。
- 负一屏关闭或非默认排序时，隐藏常用按钮并直接显示全部；只剩一种内容时隐藏整个切换组，不留下没有切换意义的单个按钮。

用户已选第 3 张作为基础，按以下规则修订，不再选择其他导航方向：

- 原“常用⌄”的位置放两个相邻的图标按钮，左侧星形代表常用，右侧四宫格代表全部。星形表示整个常用内容，不是只显示已固定应用。
- 两个按钮单击直接切换，无下拉箭头、无弹出栏、无第二行导航、无侧栏。
- 图标约 15 pt，点击区域至少 32×32 pt，建议 34×34 pt，按钮间距约 6 pt。
- 当前项使用浅色圆角底和更深图标色；另一项仅显示中性灰图标。不叠加两层胶囊边框，保持工具栏轻盈。
- 悬停显示“常用”或“全部”；VoiceOver 提供名称和选中状态；Tab 可聚焦，空格/回车直接切换。不用常驻文字换取可发现性。
- 每个内容分别恢复自己的滚动位置。主动点导航按钮时退出搜索、关闭当前文件夹，进入所点的根内容；中文组合输入未提交时先交由输入法完成，不执行中间拼音查询。
- 搜索期间按钮仍可点击；选中样式保留搜索来源，点按钮明确结束搜索并切换。Esc 的既有搜索返回逻辑保留。

原先三张概念图仅作探索记录；第 3 张修订版为当前视觉依据。只修改切换控件和角标，窗口材质、大小比例、应用网格与整体间距沿用已选图。

### 4.4 搜索、文件夹和管理

- 唤起后输入焦点进入搜索框；中文输入法组合状态由输入框优先处理。
- 输入搜索时查询全部可见 App，包括文件夹内部，不局限于常用页或当前文件夹。
- 沿用已有名称、拼音和首字母匹配及结果排序；固定不会改变搜索相关性排名。
- 搜索结果仍是网格，首次选择最佳结果；方向键按当前实际列数移动，回车启动，选择移出可视区自动滚动。
- 打开文件夹时在小窗内部进入文件夹视图，顶部出现返回入口与文件夹名；不再打开覆盖全屏的大文件夹。
- 小窗中支持启动、搜索、文件夹浏览、固定/取消固定及固定排序。首版普通页重排、跨文件夹拖放继续在全屏进行；更多菜单提供 `在全屏整理应用`。这是拟议的首版取舍。
- 现有隐藏、卸载等菜单能力可复用原有确认/设置入口，不在小窗内另建一套流程。

Esc 的优先级：输入法候选/系统菜单优先 → 清空查询并恢复搜索前浏览位置 → 退出文件夹 → 关闭小窗。每次只处理一层，不让同一按键穿透多层。

### 4.5 关闭、位置记忆与双模式同步

| 动作 | 期望行为 |
| --- | --- |
| 成功启动 App | 小窗关闭，把焦点交给目标应用，沿用一次启动计数 |
| 启动失败 | 保留小窗，显示轻量错误信息；扫描和计数遵循现有启动结果契约 |
| 点击面板外 / 重复唤起 | 关闭小窗，不拦截用户原本点击的窗口 |
| 打开右键菜单、输入法候选或设置确认框 | 不误判为外部点击而抢先关闭 |
| 再次唤起 | 查询为空，恢复本模式搜索前的常用/全部入口及滚动位置 |
| 完全退出并重启 | 全屏从原普通第一页开始；小窗从全部顶部开始，默认启动模式仍持久保存 |
| 临时切换全屏 / 小窗 | 查询和选中 App 能连续使用；两种模式各自保存浏览位置，不用一方的索引覆盖另一方 |
| 常用入口被关闭或排序改变 | 小窗回到全部；不能停留在不可访问页面 |

滚动恢复以最上方可见行的 App/文件夹身份作为锚点，避免扫描、过滤后用旧偏移落到错误内容。初次使用一种模式时可以默认定位，其后各自记忆，不强行把全屏第 N 页换算成小窗第 N 屏。

## 5. 数据与代码边界

### 5.1 数据所有权

- `RecommendationPreferences`：新增有序固定记录（applicationKey、displayName），与排除列表原子规范化和一次通知。
- `ApplicationRecommendationEngine`：把“应用可展示”与“使用次数大于零可推荐”分离；两者都过滤隐藏和无效目标，但固定不要求使用次数。
- `ApplicationRecommendationSnapshot`：保存同次展示的稳定候选顺序。主动固定操作组合固定前缀与候选补位；固定项不受推荐次数门槛影响。
- `KidoXStore`：统一解析应用身份、发布展示数据；仍为搜索与启动的唯一入口。
- 新增展示模式偏好：只保存 `fullscreen / compact`；未知值回退全屏。
- 新增小窗导航状态：常用/全部、文件夹身份、浏览锚点、搜索前位置；与 `LauncherNavigationState` 分离，均不修改真实页。

### 5.2 拟修改模块

| 文件 / 模块 | 拟修改内容 |
| --- | --- |
| `KidoX/Stores/RecommendationPreferences.swift` | 固定模型、排序、容量校验、去重、互斥偏好事务、备份默认值 |
| `KidoX/Services/ApplicationRecommendationEngine.swift` | 资格检查拆分、固定解析、稳定合并与排除 |
| `KidoX/Stores/KidoXStore.swift` | 共享数据、固定动作、小窗投影和浏览状态 |
| `KidoX/Views/ContentView.swift` | 固定菜单、辅助功能状态和固定区域拖动；不添加固定角标，保留现有文件夹点击修复 |
| `KidoX/Views/RecommendationSettingsSection.swift` | 固定列表管理与容量提示 |
| 拟新增 `CompactLauncherView` / 导航状态 / 展示偏好 | 小窗工具栏、常用/全部、搜索和文件夹内容 |
| `KidoX/App/KidoXPanelController.swift` | 单一展示协调器、模式对应窗口与背景、尺寸、焦点、外部点击和转换 |
| `KidoX/App/KidoXActivationController.swift` | 只在必要处传递唤起意图，不复制事件监听器 |
| `KidoX/Views/SettingsView.swift`、设置文案资源 | 启动方式、备份字段编码/解码与中文/英文文案 |
| `KidoXTests/RecommendationsTests.swift` 与新增针对性测试 | 固定、容量、身份、模式和旧备份回归 |

窗口可以按模式懒加载两个视图容器，但只能由一个协调器展示、共享一个 store，最多一个可见。不要创建两份扫描器、搜索索引、快捷键监听或互不一致的计数。

### 5.3 兼容与迁移

- 新固定列表缺省为空；原来的推荐、应用顺序和使用次数完全可沿用。
- 固定列表和默认展示模式随现有备份导入导出；通过可选字段兼容旧 schema 1，不因这两个功能修改 SwiftData 应用记录结构。
- 导入旧备份时固定列表恢复为空、展示模式为全屏；行为在导入说明中明确。
- 导入新备份时统一去重、固定/排除消歧、最多保留 35 个合法记录；未安装引用可保留并明确标识。
- 会话页码、小窗滚动锚点和窗口坐标不进入跨设备备份。
- 负一屏关闭只影响展示，不清空数据；切回全屏是小窗的即时回退路径。

## 6. 权限与性能

采用原生窗口和材质绘制自身界面，不采集屏幕，所以这两项功能不需要新增屏幕录制权限。已有 F4/手势能力可能依赖的权限或系统接口保持现状，不能把它们描述为小窗新增权限。

Apple 提供 [NSPanel](https://developer.apple.com/documentation/appkit/nspanel) 和 [NSVisualEffectView](https://developer.apple.com/documentation/appkit/nsvisualeffectview) 用于面板和半透明界面；具体材质受系统外观与辅助功能设置影响。无需引入 lid-plane 的屏幕采集和渲染链路。

性能策略：复用已加载图标与异步搜索索引；小窗全部列表惰性渲染；隐藏后暂停 UI 动画，不做循环屏幕采集。固定动作只重组小规模展示列表，不全量扫描磁盘。启动、滚动和文件夹点击仍需真机测量，不能用概念图或编译成功替代流畅度证据。

## 7. 验证与验收

以下为完整验收清单；本轮已实施，已执行的检查和仍需扩展验证的环境见 [实施记录](pinned-apps-compact-launcher-implementation.md)：

1. 从未启动的 App 可固定，出现在第一段；文件夹内 App 固定不离开原文件夹。

3. 隐藏 App、隐藏父文件夹、卸载/重装、排除后固定、重复 key、取消固定均符合本文规则。
4. 固定拖动不改变普通页，不触发文件夹创建；鼠标从外部移入后首次单击仍能正常启动/展开。
5. 推荐计数变化不在当前会话跳位；固定的显式调整即时反馈。
6. 旧配置、旧备份缺省值正确；新备份往返保持固定顺序、开关、布局和模式。
7. 小窗 `wx` / `xtsz` / 全拼搜索、中文输入法、方向键跨行、Esc 分层及搜索返回正确。
8. 全屏/小窗反复切换、搜索中切换、重新唤起、完全重启、关闭负一屏后重开都不会串页。
9. 快捷键、Dock、菜单栏、热角和已启用手势均遵循模式；不重复计数或重复监听。

11. 浅色/深色、降低透明度、减少动态效果、窄屏、外接屏切换、全屏 Space 均检查。
12. 同一窗口尺寸下检查：全部、6×4 常用、7×5 常用、固定不足一行、搜索结果、空结果、文件夹展开和固定管理；最后一行完整或可滚动访问。
13. 常用/全部双图标一次点击即可切换，不弹出菜单；鼠标悬停和键盘/VoiceOver 均可识别入口和选中状态。
14. 所有视图的固定 App 均无图钉、星标、圆点等角标；固定顺序、右键取消固定和设置管理仍可使用。

建议分两步实施：先做固定数据、管理和全屏交互，验证现有布局不回归；再做小窗展示、模式切换和焦点处理。
