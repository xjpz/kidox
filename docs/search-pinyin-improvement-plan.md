# KidoX 中文拼音搜索修改方案

日期：2026-09-09
状态：用户已通过“开始实现”授权；实现及安装已完成，实际验收范围见 [实施记录](search-pinyin-implementation.md)
代码基线：`main` / `1bfcf75`，叠加当前工作区已实现的推荐页和页面记忆功能

## 1. 目标与边界

让中文用户能按汉字、拼音或拼音首字母查找应用。主要验收目标是 `x` 能找到「系统设置」，`wx` 能找到「微信」，同时避免其他语言的名称因为一个字母挤入结果前列。

| 项目 | 约定 |
|---|---|
| 本轮交付 | 已审核方案、搜索实现、聚焦测试与本机安装验证 |
| 界面 | 沿用现有搜索框和应用网格，不增加搜索模式开关、标题或推荐文案 |
| 搜索范围 | 搜索全部可见应用，包括文件夹内应用；沿用现有文件/URL 搜索，不受推荐页 24 项上限限制 |
| 既有功能 | 保留推荐 24 项、无标题布局、记住上次页面、搜索来源恢复、文件夹性能与点击修复 |
| 原始数据 | 不修改应用原位置、文件夹关系、打开次数、用户改名或隐藏状态 |
| 外部服务 | 本地完成，无网络请求，不引入大型第三方词库或模型 |
| 发布 | 按会话授权替换安装版并清理临时旧包；不提交、不推送 |

## 2. 已确认的原因和证据

本机数据库中，「系统设置」和「微信」均存在且未隐藏。直接使用当前生产搜索模型读取本机记录，得到：

| 应用 | 不能命中的输入 | 当前能命中的输入 |
|---|---|---|
| 系统设置 | `x`、`xt`、`xtsz`、`xitong` | `系统`、`设置`、`sys`、`settings` |
| 微信 | `wx`、`weixin` | `微信`、`w`、`we`、`wechat` |

当前 `kidoXSearchInitials` 按空格和标点分词，取每个词的首字符；没有汉字转拼音过程。「微信」得到的是「微」，不会生成 `wx`。

另一个问题是 `localizedDisplayNames` 收录所有语言且没有保留语言来源。「预览」通过越南语别名 `Xem trước` 命中 `x`。本机复现的 10 个 `x` 结果与用户截图一致。

来源：

- [搜索归一化、首字母与匹配评分](../KidoX/Models/LaunchItem.swift)
- [候选过滤、查询缓存与结果排序](../KidoX/Stores/KidoXStore.swift)
- [应用名称及多语言名称采集](../KidoX/Services/ApplicationScanner.swift)

已对本机 Foundation 的 `.mandarinToLatin` 做独立临时脚本验证：「系统设置」生成 `xi tong she zhi`，「微信」生成 `wei xin`。同时发现「音乐」生成 `yin le`；系统能力可作为基础，但不能保证多音字总是正确。该验证不是新搜索功能的实现或验收。

## 3. 用户可见的匹配规则

### 3.1 中文、全拼与首字母并存

| 应用 | 生成的全拼 | 生成的首字母 | 应支持的典型输入 |
|---|---|---|---|
| 系统设置 | `xitongshezhi` | `xtsz` | `系统`、`设置`、`x`、`xt`、`xtsz`、`xitong`、`shezhi`、`sz` |
| 微信 | `weixin` | `wx` | `微信`、`w`、`wx`、`wei`、`weixin`、`wei xin`、`WeChat` |
| 微信开发者工具 | `weixinkaifazhegongju` | `wxkfzgj` | `微信开发`、`wxkf`、`wxkfzgj` |
| 预览 | `yulan` | `yl` | `预览`、`yl`、`yulan` |
| 音乐 | `yinyue`，词组纠正后 | `yy` | `音乐`、`yy`、`yinyue` |

规则细节：

- 汉字、英文名称、英文缩写继续可用，忽略大小写和全半角差异。
- 单个拉丁字母可匹配中文名称的拼音开头。例如 `x` 命中「系统设置」；不通过任意位置的拼音字母扩大匹配。
- 两个及以上字母支持完整首字母串及其前缀；`wx` 应优先显示「微信」，再显示「微信开发者工具」。
- 两个及以上字母可按汉字音节边界匹配后面的连续部分，例如 `sz`、`shezhi` 命中「系统设置」，权重低于名称开头匹配。首字母中间匹配须连续，不启用任意跳字。
- 保留音节边界，`wei xin` 可匹配「微信」；一般多词查询仍要求所有词命中同一个应用，不能只匹配其中一个词。
- 中英混合名称保留原英文/数字段，同时为中文段生成拼音；不把 `Xcode` 等英文名称再做汉语转写。
- 不为拼音首字母启用编辑距离或跳字模糊搜索，避免 `wx` 被扩散成大量弱相关结果。
- 完全无匹配时沿用现有空结果状态，不补入推荐应用。

### 3.2 控制其他语言别名的干扰

将搜索名称区分为有来源的候选组：

| 名称来源 | 匹配策略 |
|---|---|
| 用户改名、当前显示名称、原始包名称 | 保留现有字面匹配；对中文候选增加拼音 |
| 有明确 `zh-*` 来源的中文别名 | 支持汉字、全拼和首字母；切换英文界面后仍能用 `wx` 找微信 |
| 当前语言及英文别名 | 支持字面名称、单词前缀和英文缩写，不转换成拼音 |
| 其他语言或旧数据中无来源的别名 | 保留完整名称匹配；前缀匹配要求查询至少 3 个字符；禁用缩写、子串和模糊匹配 |
| Bundle ID | 沿用至少 3 个字符才匹配的限制，低优先级 |

非当前语言别名不参与单字母命中；长度为 1 的完整别名也不作例外。长度至少 2 的完整名称仍可查找，例如旧数据里的「微信」。因此中文界面下 `x` 不再仅凭 `Xem trước` 命中「预览」，完整输入这个别名仍可找到它。

`TextEdit` 中的 `x`、`Bluetooth File Exchange` 中的 `x` 属于原有英文名称子串匹配，仍保留，但排在明确的拼音开头匹配之后。

不能从旧的 `[String]` 别名数组可靠推断语言。扫描阶段要保留语言标识；不能把所有含汉字的日文别名都当成中文别名。

## 4. 搜索排序

默认排序下使用明确的相关度层级，按最优命中理由决定应用排名，避免现在按名称组提前返回而错过更优匹配。

| 优先级 | 命中类型 | 示例 |
|---|---|---|
| 1 | 主要名称完整匹配 | `微信`、`WeChat` |
| 2 | 全拼完整匹配，或至少 2 字母的首字母串完整匹配 | `weixin`、`wx` → 微信 |
| 3 | 主要名称或单词前缀 | `x` → Xcode；`we` → WeChat |
| 4 | 拼音全拼/首字母开头匹配 | `x`、`xt` → 系统设置；`wx` → 微信开发者工具 |
| 5 | 音节边界后缀、首字母连续片段、原有英文缩写/子序列 | `shezhi`、`sz` → 系统设置；`wc` → WeChat |
| 6 | 主要名称内部子串 | `x` → TextEdit |
| 7 | 原有名称拼写容错 | 达到既有长度条件的轻微英文拼写错误 |
| 8 | 其他语言别名、Bundle ID | 不覆盖前面的有效主要名称及拼音命中 |

单字母即使恰好等于某个中文单字名称的首字母，也按第 4 级处理，不享受第 2 级完整缩写加分。相同层级依次比较名称来源、匹配紧密程度，再沿用现有位置和显示名称排序，最后用应用 ID 保证确定性。

`x` 不保证「系统设置」是第一项，Xcode 的直接英文前缀可以靠前；但「系统设置」应排在 DBX、TextEdit 这类内部包含 `x` 的结果之前。

用户选择字母、最近打开、最常用等其他排序时，保留该排序的结果顺序；本次只统一扩大匹配集合，不暗中覆盖用户选定的排序方式。

## 5. 名称、索引与缓存的职责

### 5.1 数据来源与兼容

- `LaunchItem` 继续保存原始应用信息。
- 新增可选的带语言来源字段，例如 `localizedSearchNames: [LocalizedApplicationName]?`；元素只包含 `localeIdentifier` 和 `name`，由扫描器读取已在扫描的本地资源时生成。
- 原 `localizedDisplayNames` 字段保留，继续兼容现有名称显示和旧备份。
- 旧数据缺少新字段时正常解码，当前中文显示名称立即参与拼音索引；未知来源别名按低优先级规则处理。后台正常扫描完成后补齐来源，不阻塞启动。
- 新字段只保存原始名称及其来源，不持久化拼音派生值；不需要用户执行数据库迁移，不要求删除或重建原布局。
- 较旧版本忽略新增字段仍能读取布局；旧版本重新导出可能丢失该可选字段，新版后续扫描可恢复。

### 5.2 搜索索引

新增纯逻辑 `ApplicationSearchIndex` 与 `PinyinSearchNormalizer`，索引包括应用 ID、名称来源、归一化字面词、拼音音节、连续全拼和首字母。

- 中文来源包括 `zh-*` 本地别名、中文模式下的显示名称，以及含汉字的用户自定义名称；不向所有语言的别名生成普通话索引。
- 使用系统转写并去声调，完整词组优先转换。为实际发现的常用多音字词组增加小型、有测试的纠正表，例如「音乐」→ `yin yue`；不枚举所有多音字组合。
- `ü` 及其带调变体在去声调前归一化为 `v`，并提供 `u` 的兼容检索形式；验证 `lv` 不会被直接去重音错误地丢掉。
- 原名和用户改名均可检索；拼音只作为检索派生数据，不改变页面上的名称。
- 系统转写失败时保留原名称的搜索能力；不因一个候选转换失败而中断整次搜索。
- 生成耗时放在加载/扫描后的后台工作中；Store 持有索引，视图和按键事件只读。

### 5.3 更新时机与竞态

| 事件 | 处理方式 |
|---|---|
| 启动加载、扫描完成 | 为新增或名称变化的记录建立索引；已有有效索引继续可用 |
| 用户改名、语言切换、导入备份 | 按名称/来源/有效语言指纹更新相应索引，清理受影响的查询结果缓存 |
| 删除应用 | 移除对应索引和失效结果 |
| 隐藏/恢复应用、整理文件夹 | 候选集合立即按当前真实记录过滤，不等重新转写 |
| 打开次数或最后打开时间变化 | 不重新生成拼音；按现有排序需求更新结果缓存 |
| 连续键入 | 只匹配缓存索引，不逐字执行全量汉字转拼音或遍历应用包 |

索引缓存以应用 ID、检索字段指纹、语言上下文和规则版本为依据。查询缓存另带索引版本及当前排序/过滤状态，设置有限容量，避免每种输入永久堆积。

后台结果携带数据版本与查询版本，旧任务不能覆盖新查询。索引未就绪时，已有中文/英文文本搜索立即可用；就绪后只刷新仍然有效的当前查询。若用户已经选中应用，刷新后该应用仍在结果中则保留选择身份，避免 Return 打开其他应用。

## 7. 验收标准

### 7.1 自动化

| 编号 | 场景 | 期望 |
|---|---|---|
| S01 | 系统设置：`x / xt / xtsz / xitong / shezhi / sz` | 均命中；单字母不走拼音内部任意匹配 |
| S02 | 微信与开发者工具：`wx / weixin / wxkf` | `wx` 中微信优先于开发者工具，`wxkf` 命中开发者工具 |
| S03 | 原有中文/英文：`系统 / 设置 / 微信 / sys / settings / wechat / wc` | 既有有效输入保持可用 |
| S04 | 大小写、全角、空格、混合名称 | `WX`、`ｗｘ`、`wei xin` 与定义一致；中英混合不丢英文段 |
| S05 | 中文界面中的预览 | 不因 `Xem trước` 命中 `x`；仍可用完整别名、`yl / yulan` 查到 |
| S06 | 多语言和旧记录 | 当前语言/英文别名有效；旧无标签数据可读，后台补齐标签后相关查询缓存失效 |
| S07 | 多音字、ü、转换失败 | `音乐 → yinyue / yy`；ü 支持 v/u；失败保留原名匹配 |
| S08 | 默认排序 | Xcode 的直接前缀、系统设置的拼音开头、TextEdit 的内部子串按既定层级排列 |
| S09 | 其他排序 | 匹配集合扩展，但仍遵循用户选择的字母/次数/时间排序 |
| S10 | 文件夹内应用、隐藏、卸载 | 沿用当前可见性规则；一个应用只返回其真实记录，不引入推荐副本 |
| S11 | 改名、语言切换、扫描/备份恢复 | 索引及时失效；旧任务不能覆盖新数据；原名与自定义名均可检索 |
| S12 | 索引尚未就绪、快速输入、选择后异步刷新 | 当前查询正确，已有选择不被无故替换，清空搜索仍返回来源页 |
| S13 | 推荐/页面记忆回归 | 既有 31 项测试通过；24 项上限和恢复普通页/负一页不改变 |
| S14 | 旧新数据往返 | 缺少可选字段可读，旧布局及统计完整保留；旧阅读器可忽略新增字段 |

单字母命中不等于必须排第一；用结果包含关系和明确的相对顺序验收，避免依赖本机安装了哪些无关应用。

### 7.2 性能与本机操作

- 对 1,000 条包含中文及别名的内存记录分别测量首次索引生成、增量更新和热查询；不得把首次转写耗时藏进查询平均值。
- 目标：Release 热查询匹配与排序 p95 不超过 10 ms，连续输入时主线程不执行全量转写和应用包读取。这是待验证的预算，不是已达到的结果。
- 在相同记录上修改打开次数，验证不触发重复转写；改名只更新受影响记录。
- 本机逐一验证用户的 `x`、`wx` 例子、中文/英文输入、中文输入法组合态、方向键/Return 启动、Escape 清空、普通页和负一页的搜索来源恢复。
- 记录实际运行路径和构建身份；源码测试、构建、界面操作、安装替换分别报告。安装后不继续使用未经核对的旧进程。
- 不用覆盖用户数据库的方式制造测试条件；纯逻辑使用内存样本，正常启动测试产生的打开统计不冒称完全无数据变化。

## 8. 实施顺序、风险与回退

审核后依次完成：纯逻辑与多音字测试 → 名称来源兼容 → 索引和缓存接入 → 搜索排序 → 回归/性能/本机验收 → 按已授权范围交付安装版。

主要风险及处理：

1. 多音字不能靠通用转写完全解决。只纠正有明确证据的常用词组，并保留原名搜索；首版不承诺所有生僻多音字的所有读法。
2. 短缩写天然可能对应多个应用。通过完整缩写优先、前缀优先和确定性排序处理，不随机挑一个结果。
3. 旧别名没有语言来源。按保守规则读取，正常扫描补齐；不猜测语言、不强制丢弃旧布局。
4. 后台索引更新可能改变候选。校验版本并保持仍然有效的选中应用，避免启动目标漂移。

回退只恢复旧搜索路径，新增可选名称字段可保留并被旧逻辑忽略；不回退推荐页、页面记忆或文件夹修复。旧安装包已按用户要求清理，不能假定存在历史 `.app.backup` 可直接恢复；需要回退时从明确的源代码状态重新构建。

本方案已获准实施。以上规则作为设计基线，实际测试、性能、安装身份及尚未单独验证的场景以 [实施记录](search-pinyin-implementation.md) 为准。
